# NVKDrive

NVKDrive — учебный сервис для поиска и бронирования совместных поездок студентов. Студент может создать поездку как водитель или занять место в чужой поездке как пассажир.

## Проблема

Студентам бывает трудно найти удобную и недорогую поездку по городу: объявления разбросаны по чатам, свободные места быстро меняются, а договорённость о поездке не зафиксирована. NVKDrive собирает доступные поездки в одном месте, показывает актуальное число мест и позволяет забронировать место по понятному сценарию.

Сервис не пытается оценивать надёжность людей или гарантировать безопасность поездки. Его задача — организовать публикацию поездок и бронирование мест между студентами.

## Для кого

- Студенты вуза, которые ищут поездку по городу.
- Студенты с автомобилем, которые готовы взять попутчиков.

Проверка принадлежности к вузу, личности, документов, рейтингов и надёжности участников в MVP не входит.

## Что входит в систему

### Учётные записи и локации

- Обычная регистрация и вход по логину и паролю.
- При создании и поиске поездки пользователь выбирает точки с помощью API Яндекс Карт: сервис получает название и географические координаты места.

### Поездки

- Пользователь может создать поездку как водитель: указать точки отправления и назначения, число свободных мест, цену одного места, а также время отправления и/или прибытия. Хотя бы один из двух временных параметров обязателен.
- Цена может быть равна `0 ₽` для бесплатной поездки. Сервис не принимает платежи и не участвует в расчётах.
- Поездка отображается в списке активных поездок; список фильтруется по точке отправления, точке назначения и времени.
- Опубликованная поездка не редактируется. Водитель может завершить её вручную или отменить целиком.
- Если водитель не завершил поездку сам, сервис завершает её автоматически через два часа после указанного времени отправления или прибытия.

### Бронирования

- Пассажир бронирует одно или несколько свободных мест; бронь подтверждается автоматически, если мест достаточно.
- При бронировании нескольких мест пользователь отмечает «бронирую другому». Это позволяет занять места для попутчиков.
- Водитель не может бронировать место в собственной поездке.
- Пассажир может отменить собственную бронь; водитель может отменить бронь отдельного пассажира или всю поездку. При отмене поездки отменяются связанные бронирования.
- Водитель видит пассажиров своих поездок, пассажир — свои бронирования и их статусы.
- Пользователь может выступать водителем в одних поездках и пассажиром в других. Пересечение времени поездок и броней в первой версии не проверяется.

## Границы MVP

В систему **не входят**:

- реальные платежи, возвраты и финансовые гарантии;
- проверка личности, водительских прав, страховки, рейтинги и отзывы;
- чат, обмен контактами и уведомления между участниками;
- геолокация в реальном времени, навигация, построение маршрута и контроль автомобиля;
- редактирование уже опубликованной поездки;
- мобильное приложение и сложный пользовательский интерфейс.

## Инженерный скелет

Основная единица работы — `BookingJob` (запрос на бронирование). Предварительный жизненный цикл:

```text
Created → Confirmed → Completed
    │          │
    └→ CancelledByPassenger
               ├→ CancelledByDriver
               └→ CancelledBecauseTripCancelled

Created → Failed
```

Точные допустимые переходы и критерии приёмки зафиксированы в `docs/requirements.md`.

Сервис строится по схеме `request → Job → Dispatcher → Registry → Tool → ToolResult`:

- API получает команду пользователя и создаёт или изменяет `BookingJob`;
- `Dispatcher` выбирает обработчик через `Registry`, не зная его конкретной реализации;
- обработчики реализуют единый контракт `Tool`;
- минимум два обработчика: `BookingTool` резервирует или освобождает место, `TripCompletionTool` завершает поездку вручную или автоматически;
- обработчик возвращает `ToolResult`, из которого API формирует ответ или единую ошибку.

HTTP API будет описан в OpenAPI. Создание брони будет идемпотентной операцией по ключу идемпотентности; ошибки будут возвращаться в едином машиночитаемом формате.

Внешняя сетевая зависимость — API Яндекс Карт для поиска и геокодирования локаций. Для неё будет реализован адаптер с timeout, ограниченными повторами, обработкой некорректного ответа и fake-реализацией для тестов.

## Технологии и запуск

- Backend: C#, ASP.NET Core.
- Хранение: PostgreSQL, Entity Framework Core и миграции EF Core.
- Frontend: TypeScript и React.
- Контейнеризация и локальный запуск: Docker и Docker Compose.
