# Взлом Job — практика 3

Упражнение на паре. Вы получаете таблицу переходов Job (ту самую проверку переходов, которую на этой неделе
пишете в коде) и пытаетесь её **сломать**: найти цепочку команд, которую таблица пропускает, хотя не должна.
Потом чините таблицу — и ломаете починку соседней группы.

Сервисы те же, что на покере: [А — DocConv](variant_a.md) · [Б — Notify](variant_b.md) ·
[В — Vision](variant_c.md) · [Г — Reports](variant_d.md). Учебный пример для демо — [Calc](demo_calc.md).

## Как читать таблицу

В файле варианта — таблица: **команда | из какого состояния | в какое**.

- Команда проходит, только если в таблице есть строка **с этой командой и текущим состоянием** Job.
- Нет такой строки — **отказ**, состояние не меняется.
- Команды можно подавать в любом порядке и в любой момент.

## Команды

| Команда | Что значит |
|---|---|
| `create` | Клиент создал задание |
| `start` | Запустился Tool. **Каждый принятый `start` — это ещё один работающий Tool** |
| `finish` / `fail` | Работающий Tool прислал итог: успех / ошибку. Подать можно, только пока есть работающий Tool. Tool отвечает когда угодно: сразу, через час, после отмены |
| `restart` | Сервер перезапустился. Все работающие Tool пропали — ответа от них не будет |
| `cancel`, `retry`, `rerun`, `delete` | Команды клиента. Какие есть в вашем варианте — видно по таблице. Отмена и удаление **не останавливают** уже работающий Tool |

Названия состояний в вариантах свои: например, у Notify рабочее состояние — `sending`, готово — `sent`.
В файле варианта это указано.

Записывайте цепочку по строке на команду — что стало с Job и сколько Tool работает. Пример для [Calc](demo_calc.md):

```
create  → created, Tool: 0
start   → running, Tool: 1
start   → отказ, running, Tool: 1
finish  → done, Tool: 0
```

## Злодейства

Одинаковые для всех вариантов. Для каждого найдите цепочку команд — или убедитесь, что таблица его не пропускает.

| | Злодейство |
|---|---|
| **З1** | **Двойная работа**: в одном Job одновременно работают два Tool |
| **З2** | **Вечная работа**: сервер перезапустился, а Job так и остался в рабочем состоянии |
| **З3** | **Отменённое стало готовым**: Job отменили или удалили, а потом он стал готовым — без новой команды клиента |
| **З4** | **Два итога**: Job был в ошибке, а потом стал готовым — без новой команды клиента |
| **З5** | **Успех без работы**: Job стал `done`, не побывав в рабочем состоянии |
| **З6** | **Повтор успешного**: готовый Job снова пошёл в работу — например, SMS ушло второй раз |
| **З0** | Только в части 3: **сломали обычный путь** — после починки не работает то, что записано в варианте в разделе «Должно работать» |

Некоторые злодейства в вашем варианте невозможны — таблица их защищает. Это тоже результат.

## Группы и доска

Работаем в случайных группах до 10 человек; номер группы даёт преподаватель. Созвон внутри группы —
где вам удобно. Объявления и ссылки — в Telegram-чате курса: держите его открытым.

Вариант — по номеру группы:

| Группа | Вариант |
|---|---|
| 1, 5, 9 | А — DocConv |
| 2, 6, 10 | Б — Notify |
| 3, 7, 11 | В — Vision |
| 4, 8, 12 | Г — Reports |

**Общая доска** (ссылка — в Telegram): четыре зоны, по одной на вариант, в каждой — диаграмма варианта.
В зоне своего варианта группа создаёт **рамку «Группа N»** и работает только в ней. Чужие рамки не трогаем.

**Issue группы** — в Zadania уже есть issue `[job] Группа N` для каждой группы:
[список](https://github.com/AIProgramIngeneering2026/Zadania/issues?q=is%3Aissue+%22%5Bjob%5D+%D0%93%D1%80%D1%83%D0%BF%D0%BF%D0%B0%22).
Новые issues не создавайте — пишите комментарии в issue своей группы.

**Каждый участник группы оставляет хотя бы один комментарий** — одной строкой, злодейство первым:

| Что сделали | Комментарий |
|---|---|
| Нашли взлом | `З3: create, start, cancel, finish → done` |
| Проверили чужой | `Проверил З3 — подтверждаю` или `З3 не проходит: finish из cancelled — отказ` |
| Доказали, что невозможно | `З5 невозможно: …` и почему |

Злодейств шесть, а вас до десяти: проверка чужой цепочки и доказательство «невозможно» — такая же работа, как взлом.

## Ход пары

### Часть 1. Взлом (12:20–12:45)

1. Скопируйте диаграмму своего варианта в рамку группы. Таблица и та же диаграмма — в файле варианта.
2. Делитесь на пары или тройки — каждой 1–2 злодейства. Выписывайте цепочку по строке на команду
   (в чат группы, в рамку на доске или на листок) и сверяйтесь с таблицей после каждой команды.
3. Удалось — **комментарий в issue своей группы**: `З…: цепочка → итог`. Остальные проверяют цепочку
   и отвечают «подтверждаю» или «не проходит». На доске отметьте красным стрелки, через которые прошёл взлом.
4. В 12:40 сверьте вслух: какие злодейства прошли, какие таблица выдержала.

### Часть 2. Починка (12:45–13:00)

Нарисуйте в своей рамке **исправленную диаграмму**: ни одно злодейство не проходит, а всё из раздела
«Должно работать» в файле варианта — работает. Стрелки можно убирать, менять и добавлять, можно вводить
**новые состояния**. Команды и правила игры менять нельзя: например, нельзя решить, что отмена останавливает Tool.

Подпишите в рамке: «Починка готова», и положите **скриншот починки** в issue группы с подписью «Починка».

### Часть 3. Ротация (13:00–13:15)

Группа N ломает починку **группы N+1** (последняя группа — первой): её рамка на доске, скриншот — в её issue.
Группы N+1 нет или её issue пуст — берите следующую. Пробуйте все злодейства, включая **З0**.

- Вариант у группы N+1 другой: «Должно работать» для З0 берите из файла **её** варианта.
- Начните с цепочек, которые группа N+1 нашла в части 1, — они в её issue: закрыла ли их починка?
  Потом остальные злодейства: новые стрелки и состояния могут открыть новые дыры.
- Читайте починку буквально: чего нет на диаграмме, того нет; стрелка без подписи не считается.

Результат — **комментарий в issue группы N+1**: `Группа N: З… — цепочка` или `Группа N: выдержала`.

В 13:15 — все возвращаются в BBB на разбор.

## Что получится в итоге

Все комментарии собираем в матрицу — какие злодейства прошли в каком варианте, до и после починки.
Её и доску покажем на разборе.

| Злодейство | А | Б | В | Г |
|---|---|---|---|---|
| З1 … З6 | ✗ взломали / ✓ выдержала | | | |

## Что дальше

Домашнее задание недели — ядро **вашего** проекта: Job с проверкой переходов, Dispatcher, Registry, два Tool
и первые тесты. Каждое злодейство, которое относится к вашему Job, становится тестом: ядро должно его
отклонить. И обязательно тест на обычный путь — чтобы починка не сломала главное.
